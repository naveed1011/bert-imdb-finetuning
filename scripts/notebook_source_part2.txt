## 4. Full Fine-Tuning

Every hyperparameter, and *why*:

| Choice | Value | Rationale |
|---|---|---|
| Optimizer | AdamW, `wd=0.01` | standard for BERT; decoupled weight decay regularizes the 110M trunk |
| Learning rate | `2e-5` | the canonical BERT fine-tuning LR (Devlin et al. used 2e-5–5e-5; larger LRs destroy pretrained features) |
| LR schedule | linear decay, 10% warmup | warmup stabilizes Adam's second-moment estimates early in FT |
| Effective batch | `8 × 4 accum = 32` | gradient accumulation buys a big-batch recipe inside a 16 GB VRAM budget |
| Precision | fp16 on GPU | T4 tensor cores ≈ 2× throughput, half the activation memory |
| Epoch budget | 5 (max) | BERT on IMDB typically peaks at epoch 2–4 and then overfits |
| Early stopping | patience 2, Δ≥0.001 on **val** accuracy | checkpoint selection must never involve the test set |
| Best-model policy | `load_best_model_at_end` by `eval_accuracy` | the artifact we ship is the *validation-best* checkpoint |

**Compute budget (why this fits Kaggle):** 22,500 samples ÷ 32 effective batch ≈ 704 optimizer steps/epoch.
On a T4 with dynamic padding + fp16, expect roughly 20–35 min/epoch → the full notebook (fine-tune +
2 ablations + evaluations) lands around **2–3.5 h**, inside Kaggle's 9 h batch / 12 h interactive limits
with margin. Peak VRAM is measured and printed per run.

def make_training_args(**kwargs):
    """Cross-version TrainingArguments factory.

    The HF API evolves between major releases (e.g. `logging_dir` was removed in
    transformers 5.0; `evaluation_strategy` was renamed to `eval_strategy` in 4.41).
    Instead of pinning one version, we silently drop kwargs the *installed*
    transformers does not accept, and report what was dropped. This keeps the
    notebook runnable on whatever image Kaggle ships while documenting drift.
    """
    import inspect
    supported = set(inspect.signature(TrainingArguments.__init__).parameters)
    dropped = [k for k in kwargs if k not in supported]
    if dropped:
        print(f"  (compat note: transformers {transformers.__version__} ignores: {dropped})")
    return TrainingArguments(**{k: v for k, v in kwargs.items() if k in supported})


def best_epoch_of(tr):
    """Best epoch across transformers versions: 4.x stores `state.best_epoch`;
    5.x removed it — there we recover it from the eval log entry whose
    accuracy equals `state.best_metric`."""
    ep = getattr(tr.state, "best_epoch", None)
    if ep is not None:
        return ep
    bm = getattr(tr.state, "best_metric", None)
    if bm is not None:
        for e in tr.state.log_history:
            if "eval_loss" in e and e.get("eval_accuracy") is not None \
                    and abs(e["eval_accuracy"] - bm) < 1e-9:
                return e.get("epoch")
    return None

## 7. Ablation: Layer-Freezing Experiments

**Question:** where does the task-specific knowledge actually live inside a fine-tuned BERT?

**Background.** Probing studies (Rogers et al., 2020 — *A Primer in BERTology*) show lower encoder
layers learn general, local features (POS-tag-like, shallow syntax) while upper layers learn
task-relevant semantics. Freezing experiments turn that claim into a measurable trade-off:

| Configuration | Trainable | Hypothesis |
|---|---|---|
| **Full fine-tuning** (Section 4–6) | 100% of 110M | ceiling — all layers adapt to sentiment |
| **Top-4 layers + head** (freeze 0–7) | ~29% | upper layers carry most task adaptation; cheap-ish and nearly as good |
| **Head only — linear probe** | ~0.15% | BERT-as-feature-extractor: measures how *linearly separable* sentiment already is in pretrained `[CLS]` space |

This is also the historical root of **parameter-efficient fine-tuning**: the linear probe trains a
vanishing fraction of parameters, and modern methods (LoRA, adapters — the standard toolkit for today's
LLMs) generalize the same insight: *freeze most of the pretrained trunk, train a small set of new
parameters*. Freezing also follows the ULMFiT tradition (Howard & Ruder, 2018) of treating layers as a
budget to unfreeze gradually.

**Controls:** every ablation gets the identical protocol — same data, seed, LR recipe, collator,
early stopping, and its own one-shot pass over the sealed test set. Only the trainable-parameter
set varies. Wall-clock and peak VRAM are recorded per configuration, so the table reports
**accuracy per unit of compute**, not just accuracy.
<<<CODE>>>
# ══════════════════════════════════════════════════════════════════════════
# 7a. FREEZING UTILITIES + EXPERIMENT RUNNER
# ══════════════════════════════════════════════════════════════════════════
def freeze_all_encoder_layers(m):
    """Freeze embeddings + all 12 encoder layers → only the classifier head trains
    (a 'linear probe' of the pretrained representation)."""
    for p in m.bert.parameters():
        p.requires_grad = False
    return m


def freeze_first_n_encoder_layers(m, n=8):
    """Freeze embeddings + encoder layers 0..n-1; layers n..11 + head stay trainable.
    (Trainer's optimizer is built from requires_grad=True params only — frozen
    weights receive no gradient and no optimizer state.)
    Robust to shallow backbones (e.g. bert-tiny in smoke tests): clamps n so at
    least the top encoder layer remains trainable."""
    n_layers = len(m.bert.encoder.layer)
    n_eff = min(n, n_layers - 1) if n_layers > 1 else 0
    for p in m.bert.embeddings.parameters():
        p.requires_grad = False
    for i in range(n_eff):
        for p in m.bert.encoder.layer[i].parameters():
            p.requires_grad = False
    if n_eff != n:
        print(f"  (note: backbone has {n_layers} encoder layers — froze {n_eff} instead of {n})")
    return m


def count_trainable(m):
    total = sum(p.numel() for p in m.parameters())
    trainable = sum(p.numel() for p in m.parameters() if p.requires_grad)
    return trainable, total, trainable / total * 100


def run_experiment(exp_name, model_, epochs):
    """Identical protocol to the full fine-tune; only the trainable set differs."""
    safe = exp_name.lower().replace(" ", "_").replace("-", "_")
    trainable, total, pct = count_trainable(model_)
    print("\n" + "=" * 62)
    print(f"  EXPERIMENT: {exp_name}")
    print(f"  Trainable : {trainable:,} / {total:,} params ({pct:.2f}%)")
    print("=" * 62)

    args = make_training_args(
        output_dir=os.path.join(CHECKPOINT_DIR, safe),
        learning_rate=LEARNING_RATE, weight_decay=WEIGHT_DECAY,
        warmup_steps=int(math.ceil(len(tokenized_train) / (TRAIN_BS * ACCUM_STEPS)) * epochs * WARMUP_RATIO),
        lr_scheduler_type="linear",
        per_device_train_batch_size=TRAIN_BS,
        per_device_eval_batch_size=EVAL_BS,
        gradient_accumulation_steps=ACCUM_STEPS,
        num_train_epochs=epochs,
        eval_strategy="epoch", save_strategy="epoch",
        save_total_limit=2, save_only_model=True,
        load_best_model_at_end=True,
        metric_for_best_model="eval_accuracy", greater_is_better=True,
        logging_steps=5 if SMOKE else 100,
        logging_dir=LOG_DIR, report_to="none",
        fp16=torch.cuda.is_available(),
        dataloader_num_workers=0 if SMOKE else 2,
        seed=SEED, data_seed=SEED,
    )
    t = Trainer(
        model=model_, args=args,
        train_dataset=tokenized_train, eval_dataset=tokenized_val,
        data_collator=collator, compute_metrics=compute_metrics,
        callbacks=[EarlyStoppingCallback(early_stopping_patience=EARLY_STOP_PATIENCE,
                                         early_stopping_threshold=EARLY_STOP_THRESHOLD)],
    )

    if torch.cuda.is_available():
        torch.cuda.reset_peak_memory_stats()
    t0 = time.time()
    t.train()
    train_min = (time.time() - t0) / 60
    peak_vram = (torch.cuda.max_memory_allocated() / 1e9) if torch.cuda.is_available() else float("nan")

    preds = t.predict(tokenized_test)          # one-shot sealed test evaluation
    p_lab = np.argmax(preds.predictions, axis=1)
    test_acc = accuracy_score(preds.label_ids, p_lab)
    test_f1  = f1_score(preds.label_ids, p_lab, average="weighted")

    _bm_exp = t.state.best_metric
    _be_exp = best_epoch_of(t)
    print(f"  → test acc {test_acc:.4f} | test F1 {test_f1:.4f} | {train_min:.1f} min | "
          f"best val {_bm_exp if _bm_exp is None else format(_bm_exp, '.4f')} "
          f"@ epoch {_be_exp if _be_exp is not None else 'n/a'}")

    if torch.cuda.is_available():
        torch.cuda.empty_cache()

    return {
        "name": exp_name,
        "trainable_params": trainable,
        "trainable_pct": pct,
        "best_val_accuracy": float(t.state.best_metric) if t.state.best_metric is not None else None,
        "test_accuracy": float(test_acc),
        "test_f1": float(test_f1),
        "train_time_min": train_min,
        "peak_vram_gb": peak_vram,
        "trainer": t,
    }

## 8. Conclusions, Limitations & Reproduction

### What the ablation typically shows (FULL mode)
- **Full fine-tuning** reaches the ceiling (≈92–94% on the sealed test).
- **Top-4 layers + head** lands within ~1 point of the ceiling with ~29% of the trainable parameters —
  evidence that the *upper* layers carry most of the task-specific adaptation, consistent with
  BERTology probing results.
- **Head only (linear probe)** is clearly weaker (typically ~85–88%): sentiment is *largely* linearly
  accessible in the pretrained `[CLS]` representation, but adapting the trunk still buys real accuracy.
  It also trains fastest per epoch — the classic accuracy-vs-compute trade-off, quantified in the table.

### Limitations (stated honestly, as any report should)
1. **Single seed.** No error bars — run-to-run variance of ±0.3–0.5% is plausible; rankings near the
   noise floor would need multi-seed repetition to be trusted.
2. **Truncation at 512 tokens** discards review endings, where sentiment often resolves.
3. **Accuracy on balanced classes** is informative here, but per-class recall in the confusion matrix
   should always be checked for asymmetries.
4. **Out-of-domain generalization** (e.g. product reviews, tweets) is untested — IMDB→Amazon transfer
   is the standard next probe.
5. **Confidence ≠ calibration**: softmax scores are overconfident for fine-tuned transformers;
   temperature scaling / ECE would be needed to claim calibrated probabilities.

### Future work
- Multi-seed runs with mean ± std; paired significance tests between configurations.
- Compare against **DistilBERT** (2× faster) and **DeBERTa-v3** (SOTA ≈96%) at equal budget.
- Add a **LoRA** arm — bridging this freezing study to modern parameter-efficient LLM fine-tuning.
- Adversarial/robustness probes (negation flips, contrast sets) instead of accuracy alone.

### Reproduction
- **Kaggle (full):** GPU T4×2, Internet ON → *Run All* (~2–3.5 h). Offline: attach IMDB CSV +
  bert-base-uncased mirror (see `docs/KAGGLE_SETUP.md`).
- **Anywhere (smoke):** `SMOKE_TEST=1` → identical pipeline, tiny subsets, CPU-safe, ~5–10 min.
- Seeds are fixed (`SEED=42`, `data_seed`), versions are fingerprinted in `saved_model/environment.json`,
  and all headline numbers are machine-readable in `results/summary.json`.

### References
- Devlin, Chang, Lee, Toutanova (2019). *BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding.* NAACL.
- Maas et al. (2011). *Learning Word Vectors for Sentiment Analysis.* ACL. (the IMDB dataset)
- Howard & Ruder (2018). *Universal Language Model Fine-tuning for Text Classification.* ACL. (layer freezing / gradual unfreezing)
- Rogers, Kovaleva, Gotz (2020). *A Primer in BERTology: What we know about how BERT works.* TACL.
- Sun et al. (2019). *How to Fine-Tune BERT for Text Classification?* (fine-tuning recipe evidence)
- Hu et al. (2022). *LoRA: Low-Rank Adaptation of Large Language Models.* ICLR. (modern PEFT — the descendant of the linear-probe idea)
