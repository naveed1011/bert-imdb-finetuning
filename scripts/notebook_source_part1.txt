## 1. Data: Loading & the Split Protocol

### The v1 mistake this design exists to prevent
IMDB ships an **official 25k-train / 25k-test split** (Maas et al., 2011). In v1 of this project the
official **test** split was used for model selection during training (early stopping, best-checkpoint
picking). That is **data leakage**: every "keep or discard this checkpoint" decision was implicitly
fitted to the test set, so the reported test accuracy was optimistically biased — the number looked
good but no longer estimated generalization to unseen data.

### The protocol used from v2 onward
```
IMDB official train (25,000)
    ├── 90%  → train (22,500)   the ONLY data the optimizer ever sees
    └── 10%  → val   (2,500)    early stopping + checkpoint selection

IMDB official test  (25,000)
    └── SEALED — loaded, never touched until Section 6, evaluated EXACTLY ONCE
```
**Rule of thumb: the test set is a budget you spend once.** Touch it repeatedly (or tune against it)
and it silently becomes a second validation set.

### Data sources (auto-detected, in priority order)
1. `DATA_CSV` env var → explicit CSV path (any environment)
2. **Hugging Face Hub** official split → default when internet is available (results comparable to literature)
3. **Kaggle-attached CSV** (e.g. `lakshmi25npathi/imdb-dataset-of-50k-movie-reviews`) → offline fallback.
   The CSV pools the official train+test reviews, so membership of the official split cannot be
   recovered; we rebuild a **stratified 45% / 5% / 50%** split (same sizes as the official protocol).
   Numbers from this mode are internally comparable, not literature-comparable.

def find_attached_csv():
    """Scan /kaggle/input for an attached IMDB CSV (any common naming)."""
    patterns = [
        "/kaggle/input/*/IMDB*Dataset*.csv",
        "/kaggle/input/*/IMDB*.csv",

def imdb_from_csv(path):
    """Load a 50k-review CSV and rebuild train/val/test at the official ratios
    (45% / 5% / 50%), stratified by label so both classes keep parity everywhere."""
    df = pd.read_csv(path)
    text_col = "review" if "review" in df.columns else "text"

    if "sentiment" in df.columns:                       # lakshmi25npathi format: review, sentiment
        sent = df["sentiment"].astype(str).str.strip().str.lower()
        keep = sent.isin(["positive", "negative"])
        df, sent = df[keep].copy(), sent[keep]
        labels = (sent == "positive").astype(int).values
    elif "label" in df.columns:                         # alternative mirrors: text, label
        lab = df["label"].astype(str).str.strip().str.lower()
        keep = lab.isin(["positive", "negative", "0", "1"])
        df, lab = df[keep].copy(), lab[keep]
        labels = lab.map({"negative": 0, "positive": 1, "0": 0, "1": 1}).astype(int).values
    else:
        raise ValueError(f"{path}: expected a 'sentiment' or 'label' column, got {list(df.columns)}")

    clean = pd.DataFrame({"text": df[text_col].astype(str).values, "label": labels})
    trainval, test  = train_test_split(clean, test_size=0.50, stratify=clean["label"], random_state=SEED)
    train, val      = train_test_split(trainval, test_size=0.10, stratify=trainval["label"], random_state=SEED)

    to_ds = lambda d: Dataset.from_pandas(d.reset_index(drop=True), preserve_index=False)
    return to_ds(train), to_ds(val), to_ds(test)

## 2. Tokenization: From Text to Tensors

BERT does not see words or characters — it sees **WordPiece subwords** as integer IDs. Three tensors
describe one example:

| Tensor | Meaning |
|---|---|
| `input_ids` | vocab IDs, framed by `[CLS]` (start / classification summary slot) and `[SEP]` (end) |
| `attention_mask` | `1` = real token, `0` = padding — tells attention what to ignore |
| `token_type_ids` | sentence A vs B (all zeros here; matters for sentence-pair tasks) |

For classification, the final hidden state at `[CLS]` becomes the whole review's representation —
the head in Section 3 is a single `Linear(768 → 2)` on top of it.

### A deliberate change from v2: dynamic padding
v2 tokenized with `padding="max_length"` → **every** review, even a 20-word one, became a 512-token
tensor. Attention compute scales with sequence length, so most of the GPU budget was spent on `[PAD]`
tokens. v3 stores sequences at their **natural length** and lets a `DataCollatorWithPadding` pad each
*batch* to the longest member *of that batch*. Same math, far less wasted FLOPs (IMDB reviews average
~230 words, so ~2× less padding work on average) and less memory — the reason batch 8 fits comfortably
on a 16 GB T4.

**Truncation is a real modeling trade-off**: sentiment cues can sit at the *end* of a long review, and
`truncation=True` keeps only the first `MAX_LEN` tokens. We quantify exactly how much signal is cut below.

## 3. Model: BERT-base + Classification Head

`bert-base-uncased` (Devlin et al., 2019): 12 transformer encoder layers, hidden size 768,
12 attention heads, ~110M parameters. For sequence classification, Hugging Face appends a head:

```
[CLS] review tokens [SEP]  →  12 encoder layers  →  pooled [CLS] (768-d)  →  Dropout  →  Linear(768→2)
```

The head is randomly initialized — **that ~0.15% of parameters is the only part that starts from
scratch**; everything else begins from masked-LM pre-training on BookCorpus + English Wikipedia.
This asymmetry (huge pretrained trunk, tiny fresh head) is exactly what Section 7 exploits.

`id2label` is set explicitly so every report, plot and prediction speaks *NEGATIVE/POSITIVE*
instead of the meaningless `LABEL_0/LABEL_1` (a small readability fix over v2).

# 3b. METRICS & DATA COLLATOR
# ══════════════════════════════════════════════════════════════════════════
def compute_metrics(eval_pred):
    """Runs at every evaluation; results land in trainer.state.log_history
    and drive early stopping + best-checkpoint selection."""
    logits, labels = eval_pred.predictions, eval_pred.label_ids
    preds = np.argmax(logits, axis=1)
    return {
        "accuracy":  accuracy_score(labels, preds),
        # weighted averages: with balanced classes they ≈ macro averages,
        # but they stay meaningful if a subset (e.g. smoke test) is skewed.
        "f1":        f1_score(labels, preds, average="weighted", zero_division=0),
        "precision": precision_score(labels, preds, average="weighted", zero_division=0),
        "recall":    recall_score(labels, preds, average="weighted", zero_division=0),
    }
